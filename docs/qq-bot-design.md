# QQ 官方机器人绑定与昨日日报设计

## 功能范围

用户把目标 QQ 群里的成员身份绑定到自己的作战档案账号，并在网页上为该群开启日报分享。之后在该群发送 `@机器人 日报`，机器人回复该用户的昨日战绩摘要。群分享默认关闭，用户可以逐群停用或解绑。

首版使用 QQ 官方机器人和纯文本被动回复。战报使用已导入的对局数据，详细对局和可选 AI 复盘继续在网页登录后查看。

## 绑定流程

1. 用户先添加 QQ 机器人，然后在目标群发送 `@机器人 绑定`。
2. 接入服务验证回调签名，从事件中取得机器人 AppID、群 `group_openid`、发送者 `author.member_openid` 和原消息 ID。
3. 机器人用原消息 ID 把随机绑定码私聊回复给同一个发送者。QQ 官方要求双方已建立好友关系。私聊发送失败时，群内只提示添加机器人后重试，服务端废弃这次签发的码。
4. 用户登录作战档案，在「档案管理 → QQ 绑定」输入绑定码，由服务端将该群成员身份关联到当前登录账号。完成后用户可单独开启当前群的日报分享。开关旁应写明「本群成员可看到你分享的战绩摘要」。
5. 绑定页显示已有绑定和各群的分享状态。关闭分享时保留绑定，解绑时移除该群身份与档案账号的关联。换群时由用户重新授权。

绑定码建议 10 分钟有效，由安全随机数生成器签发，后端只保存带服务端密钥的 HMAC 摘要。兑码必须经过网站会话和 `Origin` 校验，并限制尝试次数。码的有效性校验、绑定写入和核销放在同一事务中。绑定冲突时保留原归属，由原账号解绑后才能重新绑定。

QQ 身份的匹配键为 `(bot_app_id, group_openid, member_openid)`。群内昵称可以作为展示信息。群身份与私聊身份分别按官方场景处理，私聊在此流程中只作为绑定码的送达渠道。

[QQ群 @ 机器人事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html) · [QQ 消息收发规则](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)

## 日报流程

1. 订阅 `GROUP_AT_MESSAGE_CREATE`，识别纯文本指令 `日报`。服务端从验签通过的事件确定当前群和命令发送者，按对应绑定解析档案账号。
2. 检查该群的分享权限。未绑定时提示绑定，分享关闭时提示登录网页开启。两种提示均不披露账号身份和战绩。
3. 将 QQ 消息发送时间转换为北京时间，计算其前一天，查询当天 00:00 到次日 00:00 之间的对局。以原消息时间计算，避免跨午夜处理或重试时日期偏移。
4. 复用网页昨日战报的取数和聚合逻辑，继续默认排除疑似直接退出的对局。首版群内字段为日期、有效局数、胜场、负场、胜率和击破首领的对局数。
5. 发送前再次检查分享权限，用原消息的 `msg_id` 和固定的 `msg_seq` 被动回复当前群。昨日没有有效记录时回复「昨日暂无已导入的有效对局」。

群回复示例（数字为示意）

> 昨日战报 · 2026-11-24<br>
> 8 局 · 5 胜 3 负 · 胜率 62.5%<br>
> 击破首领 3 局

现有入口位于 [日报查询](../backend/logbook/api.py#L244)、[日报汇总](../backend/logbook/daily_review.py#L48) 和 [日期及退出过滤](../backend/logbook/records.py#L175)。实现时可将按用户和日期取数的函数抽为共享业务逻辑，由网页和机器人各自完成身份校验后调用。群消息接口见 [QQ 发送群聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。

## 数据与权限设计

| 数据 | 建议保存内容 | 约束 |
| --- | --- | --- |
| QQ 绑定 | 档案用户 ID、AppID、群 OpenID、群成员 OpenID、分享状态、绑定时间 | QQ 群成员身份按 AppID 和群唯一。同一档案账号可绑定多个群。 |
| 绑定挑战 | 绑定码 HMAC、对应群成员身份、过期时间、核销状态 | 单次使用，过期后清理。 |
| 事件及回复状态 | 平台事件或消息标识、命令类型、处理和发送状态 | 保留到覆盖事件重投与回复重试所需的时间。 |
| 审计记录 | 绑定、解绑、分享开关、发送结果及时间 | 只记录定位问题所需字段。 |

- **回调隔离。** 通过 Caddy 将专用 HTTPS Webhook 路径转给 QQ 接入服务。按 QQ 官方协议处理回调地址验证，对业务事件用原始请求体验证 Ed25519 签名。随后校验时间戳和事件类型，限制请求体大小，再登记去重和入队。网页的登录、会话和 `Origin` 校验继续生效。 [QQ 事件订阅](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html) · [QQ 回调验签](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/sign.html)
- **限制数据访问。** 正式环境建议由独立的 QQ 接入进程接收回调，通过仅内网可达且具备服务间鉴权的接口查询允许发布的摘要。内部接口根据经过校验的群成员身份查绑定，不开放通过任意用户 ID 读取战绩的入口。QQ 接入进程只持有自己的平台和内部接口凭证。
- **幂等和限流。** 回调重复投递时，按机器人和事件或消息标识只安排一次处理。重试同一条群回复沿用原 `msg_id + msg_seq`，只有在官方回复有效窗口内重试。对发码、兑码和日报按场景设置限流，阻止批量试码及刷屏。 [QQ 消息去重和时效](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)
- **控制外发。** 群回复只允许摘要字段，目标群来自原始签名事件。取消授权后，待处理任务重新检查权限并停止发送。已经发到群里的消息仍可能被看到或留存，网页应在启用分享时说明。
- **密钥与日志。** Bot Secret、内部鉴权密钥和绑定码 HMAC 密钥放在服务端密钥配置中。日志排除绑定码、聊天原文、回调原文和令牌。现有森空岛导入令牌与成就 `u8_token` 以文本字段保存，公网接入时优先迁移到应用层加密，密钥与数据库和备份分开管理，并隔离机器人进程对这些表的访问。 [森空岛令牌表](../backend/migrations/versions/0003_skland_import_tokens.py#L11) · [成就令牌表](../backend/migrations/versions/0002_achievements.py#L15)

## 实施与验收

1. **验证平台能力。** 在 QQ 官方沙箱验证当前 BotAppID 能接收群 @ 事件、能在好友关系下私聊回复原发送者，以及能用原 `msg_id` 被动回复群消息。上线权限以该机器人的开放平台配置为准。
2. **实现网页绑定和授权。** 为 PostgreSQL 添加迁移，同步 SQLite 表结构。验证过期码、重复兑码、并发兑码、绑定冲突、跨群隔离和解绑。
3. **接入日报。** 覆盖有战绩、无有效战绩、未绑定、分享关闭、跨午夜重试和重复回调。核对同一账号、同一天的网页和 QQ 胜负统计一致。
4. **核对部署权限。** 验证伪造或过期回调会被拒绝，撤销后的待处理任务不会发送，QQ 接入进程无法读取用户会话和导入令牌，正常及错误日志均不会记录绑定码或凭证。
